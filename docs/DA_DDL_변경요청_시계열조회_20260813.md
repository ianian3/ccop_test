## 1. DA 변경 요청 (1건) — ✅ **완료 (2026-08-13)**

> **DA 신설 완료**: `TB_SYS_LGN_EVT_T.CNTN_TYP_CD` **character(3)** '접속타입코드'. 표준용어사전 등록어로 `ACCS_TYP_CD` → **`CNTN_TYP_CD`** 확정(CNTN=접속). 접속일시 `CNTN_DT`(timestamp w/tz)도 함께 매핑. 온톨로지 `vt_access.std_columns`(`access_dt`↔`CNTN_DT`, `access_type`↔`CNTN_TYP_CD`) 반영 완료. 코드값 3자리(web/comm/banking)는 다른 `_TYP_CD`처럼 공통코드 별도 관리.
> 📎 DDL: `CYBERCOP_STANDARD_TABLE_DDL_20260813.sql` · 명세서: `v0.9.5(SKAI)`.

### ② `access_type` 컬럼 추가 — **코드 컬럼이라 3요소 한 세트 필요** (아래는 요청 당시 기록)
`_CD`(코드 컬럼)는 "컬럼 추가"만으론 부족 — 기존 관례(`DLNG_SE_CD='01'/'02'`)처럼 **코드값 정의 + 공통코드 등록**이 함께 있어야 DA가 바로 작업 가능.

```
[신설] TB_SYS_LGN_EVT_T . ACCS_TYP_CD
 · 타입    : varchar(20)          (관례: ACTN_CD varchar20, DLNG_SE_CD varchar10, CALL_TYP_CD varchar30)
 · 한글명  : 접속유형코드
 · 필수    : N (기존 데이터 소급 대비), Default 없음
 · 코드값  : 공통코드 TB_COM_C 에 그룹 'ACCS_TYP' 신설 + 3건
      '01' web      (웹 접속)
      '02' comm     (통신 접속)
      '03' banking  (뱅킹 접속)
 · 근거    : 온톨로지 V4.6 R8 — vt_access 서브타입
```

| 요소 | 내용 |
|---|---|
| ① 컬럼 | `TB_SYS_LGN_EVT_T.ACCS_TYP_CD` varchar(20) '접속유형코드', 필수 N |
| ② 코드값 | `'01'`web · `'02'`comm · `'03'`banking |
| ③ 공통코드 | `TB_COM_C` 에 그룹 `ACCS_TYP` + 코드 3건 등록 |
| 현황 | web 속성(`USER_AGNT_CN` 등)은 있으나 서브타입 구분 컬럼 부재 |
| 대안 | 신설 불가 시 `SERVICE_NM`/`TRGT_URL_ADDR`로 ETL 추론 가능한지 확인 |
| 정합 | `vt_access.access_type` ↔ `ACCS_TYP_CD` (코드→web/comm/banking 디코딩은 ETL) |

> ※ 컬럼 영문명·그룹코드는 DA 표준용어 규칙에 맞춰 최종 확정 요청.

## 2. 적재 규약 확정 (DA 변경 불필요)

### ① CALL_HR 형식 = 시분초(HHMMSS) → 초 변환
- **DA 확정**: `CALL_HR` = `character(6)` = **시분초(HHMMSS)** (예: `'000300'` = 0시03분00초).
- 온톨로지 `vt_call.call_dur_sec` = **초(정수)**.
- **변환 규칙**: `call_dur_sec = HH*3600 + MM*60 + SS` — 적재 시 문자 HHMMSS를 파싱해 초로.
- **반영**: `ontology_service.py` `vt_call.std_columns` 주석에 변환 규칙 명시 완료.

### ③ ip_role = 그래프 계산값 유지 (DDL 저장 안 함)
- **결정**: `TB_IP_ADDR_M`에 `ip_role` 컬럼 **추가하지 않음**.
- 온톨로지 파생(`ip_role_temporal.py`의 `compute_ip_role_timeline`·`classify_role`)으로 **그래프에서 산출**.
- 표준 DDL은 원천 지표(`VPN_YN`·`TOR_YN`·`HOSTING_YN`·`ABUSE_SCR`)만 제공 → 이를 입력으로 그래프에서 `ip_role_current`/`ip_role_timeline` 계산.

### ④ 시각 ISO8601 적재 규약 (핵심)
- **표준 형식**: `YYYY-MM-DDTHH:MM:SS+09:00` (예: `2026-01-15T09:30:00+09:00`) — **고정폭 + 타임존 `+09:00`(KST) 통일**.
- **이점**:
  1. **문자열 비교 = 시간순** — ISO8601 사전식 정렬이 시간 순서와 일치 → `WHERE e1.dlng_dt <= e2.dlng_dt` 를 캐스팅 없이 사용.
  2. **인덱스 활용** — 문자열 그대로 비교하면 인덱스 탐. 캐스팅(`::timestamp`)하면 인덱스 못 탐(느림).
- **변환(DDL→그래프)**: DDL `timestamp with time zone` → 적재 시 `to_char(DLNG_DT, 'YYYY-MM-DD"T"HH24:MI:SS+09:00')` 로 ISO8601 str.
- **금지**: 가변폭(`2026-1-15 9:30` → `'9:30'>'10:30'` 오판) · 타임존 혼재(`+09:00` vs `Z`) · 형식 혼재(캐스팅 강제 → 인덱스 손실).
