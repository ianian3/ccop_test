## 2. 수사 분석 — IP 기반 사용자 특정 (실측)

### ★ 핵심 — 콜센터 IP → 실명 105명
| 대상IP (콜센터) | 실명 특정 인원 | 대표 실명 | 교차 |
|---|---|---|---|
| **122.54.197.66** | **64명** | 조정진·이강은·제갈진희·오호균 | EP6 카톡 19계정 + EP3 070 |
| **122.54.197.65** | **40명** | 이태준·전규호·정다운·김성수 | EP3 070 명의(권선미·차승재) + EP6 카톡 |
| 27.193.61.154 | 1명 | 조정모 | EP3 070(윤준호) |

- **대상IP 3개 전부 EP3 070/통화 IP와 일치**(122.54.197.65·66, 27.193.61.154), 2개는 EP6 카톡과도 일치.
- 의미: EP3(070 명의)·EP6(카톡 명의)는 위장이고, **접속 IP를 네이버 역조회하면 그 뒤의 실사용자(실명·휴대폰)가 드러난다**. 콜센터 IP 1개당 수십 명이 특정 = 조직 규모.

### 보강 트랙
- **043 금융 계좌**: IP로 특정된 대상자(이미나 등)의 은행 거래내역 → 자금흐름 62건. 계좌주 vt_psn + has_account.
- **044 카카오 친구망**: IP역조회 대상자의 카톡 친구 603관계 — 조직 구성원 간 연결망.

## 3. EP7의 수사적 의미
EP1~5(무엇·명의·자금) → EP6(통신수단이 콜센터 IP로 수렴) → **EP7(그 IP를 역조회해 실사용자 실명 특정)**. 이것이 "명의자 뒤 실사용자"를 묻던 EP1의 미해결 과제(Who의 최종 답)를 IP 경로로 푸는 단계. 통합 그래프에서 EP3/EP6의 IP 노드와 EP7 실명(vt_psn)이 `used_ip`로 이어져, 070·카톡·계좌를 실명 인물로 수렴시킨다.

## 4. 데이터 이슈·교훈
1. **043 은행별 헤더 상이**: 국민/하나는 계좌주 컬럼, 기업은 구분 컬럼 부재(첫 셀이 값), 신한은 예금주 별도행 → 헤더 자동매핑 + 상단 "예금주:" 추출로 대응. **기업(송주혁)·신한(조승연)은 헤더 특이로 일부만 적재 — 보강 필요**.
2. **적요 오추출 차단**: 043 상대명은 소비처(떡볶이·마트·Toss)·이체메모(대체·타행송금)라 사람이름만 dpstr(030 파서 교훈 동일 적용).
3. **044 docx 이름 매핑**: 파일명 이름(김유정·조정모)과 친구 전화 연결 근거 부족 → 친구 전화만 vt_id 등록(무리한 명의 연결 회피).
