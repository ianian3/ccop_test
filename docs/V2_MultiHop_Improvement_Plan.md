# 🚨 CCOP Text2Cypher V1: 다중 홉(Multi-Hop) 추적 한계 및 V2 고도화 방향

## 1. 이슈 개요 (사용자 수동 벤치마크 발견 사항)
- **발견 일시:** 2026년 3월 25일
- **테스트 시나리오:** 특정 ATM 기기(`ATM-부산001`)에서 입금한 사람(소유자)의 이름을 역추적하는 시나리오
- **테스트 질의문:** `"특정 ATM 번호가 '001'인 기기에서 돈을 입금시킨 사람들의 이름 찾아줘."`
- **문제 증상:** AI가 4단계 거리를 건너뛰고 존재하지 않는 `(ATM) -> (계좌)` 라는 2단계 직결 쿼리(환각)를 생성하여 **조회 결과 0건** 발생.

---

## 2. 문제 원인 분석 (AI 과적합 및 학습 데이터 부족)

### 🧩 KICS 온톨로지 상의 정상적인 4단계 추적 경로
어떤 인물이 ATM에서 돈을 보낸 것을 추적하려면 DB 상에서 아래의 **4단계 다리(Hop)**를 차례대로 건너야만 합니다.
> `[1.사람(vt_psn)]` ↔ `[2.계좌(vt_bacnt)]` ➡️ `[3.이체내역(vt_transfer)]` ➡️ `[4.ATM기기(vt_atm)]`

### 🤖 AI의 오류 (환각) 원인
1. **단어 과적합 (Word Overfitting):** AI 모델의 가중치(Weight)가 과거 파인튜닝 시 `입금=from_account/to_account` 조건에 매우 강하게 결속(Overfitting)되어 버림.
2. **다중 홉(Multi-Hop) 시나리오 학습 부재:** V1 모델을 학습시킨 SFT 데이터셋 1만 건 내에, 1~2단계 조회 쿼리 위주로만 데이터가 편중되었으며, **ATM이나 IP 주소에서부터 사람 노드까지 3단계를 초과하여 역추적하는 'Deep Traversal' 훈련 예제가 누락**됨.
3. **프롬프트 힌트 무시:** 시스템 백엔드에 4단계 경로를 강제로 알려주는 지침 가이드(Few-Shot)를 주입했음에도 불구하고, AI 모델이 자신의 학습된 본능(과적합)을 이기지 못하고 스스로 경로를 2단계로 임의 단축시켜버림.

---

## 3. 현 V1 버전을 위한 임시 우회 수사 기법 (Workaround)
V1 모델의 구조적 한계상, 거리가 너무 먼 단어를 한 번에 검색하면 중간 다리를 자체 생략해버립니다. 따라서 **꼬리물기 식 2단계 분할 수사**를 권장합니다.

*   **STEP 1 (ATM ↔ 이체 ↔ 계좌 추적):** `"ATM 기기 '001'로 입금된 이체내역과 해당 출금 계좌를 찾아줘."`
*   **STEP 2 (계좌 ↔ 사람 추적):** `"(STEP 1에서 확보한) 특정 계좌번호를 보유한 주인을 모두 나열해."`

---

## 4. 🚀 V2 모델 파인튜닝(SFT) 시 데이터셋 개선 전략
이번 B2C 테스트로 확인된 치명적 약점(Blind Spot)을 영구적으로 제거하기 위해, **차기 V2 모델 고도화** 시 기계 학습 파이프라인에 다음 과정을 필수적으로 반영합니다.

1. **복합 다중 홉(Multi-Hop) 데이터셋 1,000건 이상 증강 생성**
    *   `ATM기기 -> 이체내역 -> 계좌 -> 사람` (자금 세탁 역추적 패턴)
    *   `IP주소 -> 로그인 이력 -> 통신기기 -> 사람` (보이스피싱 사이버 패턴)
    *   위와 같이 3~5단계를 건너뛰어야만 하는 복잡한 그래프 시나리오를 합성하여 대량의 데이터셋 추가.

2. **단어-관계 강제 결속 해제 (De-biasing)**
    *   '입금/출금' 단어가 무조건 계좌와 직결된다는 고정관념 데이터 해소.
    *   주어/목적어가 모호하더라도 온톨로지 룰에 맞춰 우회 경로를 짜도록 LoRA 재학습 수행.

3. **엔티티 자동 치환(Entity Auto-Replacement) 로직 예외 처리**
    *   ATM 명칭(예: '부산001') 내에 포함된 지역명이 '부산은행(032)' 코드로 백엔드 단에서 강제 오동작 치환되지 않도록 RAG 파이프라인 예외 정규식 추가.

> **💡 요약:** 수사관님의 날카로운 수동 QA 벤치마크 덕분에, 오픈 전에 AI 엔진의 구조적 환각(단축 오류)을 완벽하게 진단해낼 수 있었습니다. 해당 보고서는 V2 CCOP 업그레이드의 핵심 나침반으로 활용될 것입니다.
