## 4. 신규 회귀 분석 — 분포 시프트 가설

### chain (-13.3p) 회귀 원인 추정
- v41 의 chain 시드 98건은 4-hop pt_cluster → 피의자 → 계좌 → 이체 패턴 중심
- 232문항의 chain 15문항은 다양한 3-hop 패턴 (서비스→통화, 사이트→IP→사건 등)
- **시드 분포 ≠ 평가 셋 분포**

### 1hop_person (-12p) 회귀 원인
- v41 학습 데이터에서 1hop_person2person 의 비중이 증가 (297 시드)
- 모델이 person↔person 관계 학습에 편향 → person↔object (계좌/전화) 관계 학습 약화
- 평가 셋: has_account / owns_phone / drives / works_at 등

### 1hop_event / threat_filter 회귀
- meta_condition 시드 290건이 threat_score / risk_level 등 메타 속성 강조
- 결과적으로 raw event 관계 (caller/callee/from_account) 표현력 일부 손실

## 8. 결론

### 핵심 발견
1. 🎯 **목표 카테고리 1hop_person2person 완전 복원** (60→80%, +20p)
2. 🟡 **meta_condition 부분 회복** (53→60%, +7p, 목표 75% 미달)
3. ⚠️ **신규 회귀 4 카테고리**: chain (-13.3p), 1hop_person (-12p), threat_filter (-8.3p), 1hop_event (-6.7p)
4. ✅ **V4.0 약점 (M~T 50/50 100%) 유지** — v40 시드 보존 성공
5. ✅ **V3.7 신규 (22/25 88%) 유지** — 회귀 없음

### v41 학습의 의미
- **단일 회귀 복원에는 성공** — v40 의 -20p 회귀를 +20p 로 정확히 되돌림
- **그러나 다른 카테고리 분포 시프트** — 시드 비대칭으로 인한 trade-off
- **시드 양 ≠ 정확도** — 시드 분포가 평가 셋과 정합되어야 효과 발현

### 한계 확인
- v37→v38 (+20.4p) → v38→v39 (+9.2p) → v39→v40 (+1.3p) → v40→v41 (-2.2p)
- **한계 효용 체감 + 분포 충돌** — 같은 베이스 모델 + 동일 학습 방식으로 81% 천장 도달

## 10. 시드 설계 교훈 (v42 적용)

### v41 에서 배운 것
1. **표적 시드 효과는 정확하나 다른 카테고리 분포 시프트 위험**
2. **시드 양만 늘리는 것은 한계** — 다양성/분포 정합이 결정적
3. **회귀 영역의 평가 셋 분포 사전 분석 필요** — 시드 설계 전 평가 패턴 확보

### v42 설계 원칙
1. **회귀 카테고리 평가 셋 패턴 사전 카탈로그화** → 시드 분포를 평가 셋과 정합
2. **v40 + v41 시드 모두 보존** (1hop_person2person 80% 유지)
3. **시드 카테고리간 비중 균형** — 200~250 단위로 균등 분포
4. **상호 충돌 패턴 사전 점검** — meta_condition 시드가 threat_filter 약화시키지 않도록
