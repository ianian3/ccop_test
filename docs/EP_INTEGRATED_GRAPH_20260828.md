## 2. EP 교차 — 통합의 핵심

### ★ 최다교차 IP (여러 통신수단이 한 거점으로)
| IP | 교차 EP (ep_origin) | 잇는 통신수단 |
|---|---|---|
| **122.54.197.66** | ep3·4·6·7·8 (5) | 070 + 통화 + 카톡 + 네이버역조회 |
| **122.54.197.65** | ep3·4·6·7·8 (5) | 〃 |

### ★ 콜센터 IP `122.54.197.66` 수렴 구조
```
122.54.197.66
├─ vt_telno 2  →  07078897940(김석혁) · 07078890431(노진성)   [070 명의 = 위장]
├─ vt_id 19 (kakao)                                          [카톡 계정]
└─ vt_id 64 (naver) ─registered_to→ vt_psn 64명              [네이버 실명 = 실사용자]
     강재호·권도형·김민욱·강미연·고일도 …
```
→ **명의(070·카톡)와 실사용자(네이버 실명)가 한 IP로 묶임**. 콜센터 거점에서 다수 명의를 운용하고, 그 뒤에 실명 인물들이 있음이 그래프로 드러남.

## 3. 수사적 의미
EP1(신고)~EP8(카톡·IP역조회)의 단서가 **하나의 그래프에서 콜센터 IP를 축으로 수렴**한다. 070 인터넷전화·카카오·구글·네이버·계좌가 서로 다른 EP·다른 가명으로 흩어져 있어도, 공유 IP·계좌·전화가 이들을 **실명 인물로 묶는다**. 이는 EP9~10(출입국으로 피의자 특정→체포)의 수사 결론을, 정형 데이터만으로 재현·검증한 것이다.

**활용**: `MATCH (i:vt_ip) WHERE i.ep_count≥'4'` 로 핵심 거점 IP를 뽑고, 그 IP에 `used_ip`로 연결된 070·카톡·네이버 실명을 펼치면 조직 거점별 구성원이 드러난다.

1. **vt_psn 이름 병합**: EP마다 가명이 달라 대부분 안 겹치나, 같은 가명은 병합됨(동일인 가정) — sameAs 후보 검토로 정밀화 필요.

3. **EP9~10 미포함**: 서술 PDF(OCR)라 정형 부재 — 통합은 EP1~8 정형만.
4. **재현**: `python3 scripts/build_integrated_graph.py` (멱등, DROP 후 재생성).
