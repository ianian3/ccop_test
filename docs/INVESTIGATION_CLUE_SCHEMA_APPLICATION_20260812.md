# 수사단서 연관관계 스키마 — CCOP 적용 방안 (검토 결과 + 실행 계획)

> **작성일**: 2026-08-12
> **대상**: `수사단서 연관관계분석 스키마_20260810.pptx`
> **선행 문서**: `docs/INVESTIGATION_CLUE_SCHEMA_ALIGNMENT_20260810.md`(정합 검토), `docs/DA_DDL_변경요청_수사단서스키마_20260811.md`(DDL 요청)
> **결론 한 줄**: 원본 스키마는 CCOP와 충돌 없이 매핑되며, 표준 DDL이 대부분 이미 반영하고 있어 **적용은 기존 파이프라인 재사용으로 저비용·무재학습**이다. 남은 실작업은 DDL 2건(DA)과 매핑 확정뿐이다.

---

## 1. 검토 결과 요약

| 축 | 결과 |
|---|---|
| 엔티티 매핑 | 11종 → CCOP 노드 **100% 대응**(누락 0) |
| 보완 항목 | 5건 도출 |
| 표준 DDL 대조 | **4건 이미 반영**(개인정보 해시·역할코드·ID타입·개통해지일), **2건만 신규**(법인대표·직업) |
| 패러다임 | ERD(속성 집약) ↔ 그래프(엣지) — 상호 변환 가능 |

→ 적용의 걸림돌이 거의 없다. "새로 만들기"가 아니라 "매핑·연결"이 핵심.

## 2. 적용 방안 — 4단계

### 2.1 [P1] DDL 반영 (DA팀 협업)
- **요청 2건** — `TB_INST_RPRS_REL_T`(기관대표자관계) 신설 · `TB_PSN_M.OCCP_NM`(직업) 추가. (상세: DDL 요청서)
- **나머지**는 기존 표준 DDL 활용(변경 불필요).
- 산출: DA 회신 + 코드값 정의서(`ROLE_CD`·`ID_TYP_CD`).

### 2.2 [P2] 온톨로지 매핑 확정
| 원본 | CCOP 반영 |
|---|---|
| 개인/법인/사건 | `vt_psn`/`vt_org`/`vt_case` (식별자 → 대리키+해시) |
| "전화번호(복수)" 등 소유 속성 | **엣지**: `owns_phone`·`has_account`·`used_ip`·`uses_id`·`uses_email`·`owns_wallet` |
| 법인 대표 | `vt_org`─[대표자]→`vt_psn` (P1 DDL 후) |
| 사건–인물 | `suspect_in`/`victim_in`/`witness_in` (`ROLE_CD` 매핑) |
| SNS/닉네임 | `vt_id` + `id_type` |
| 개통·개설일 | `valid_from`/`valid_to` (v4.6) |

### 2.3 [P3] 적재 파이프라인 (RDB → 그래프)
- **기존 `rdb_to_graph_service` 재사용** — 신규 노드·엣지 0.
- "(복수)" 속성이 엣지로 전개되도록 매핑 테이블만 추가.
- v4.6 시간축(`used_ip.valid_from/to` 백필) 이미 반영 → 개통/개설일도 동일 경로.

### 2.4 [P4] 검증
- 매핑 정합성 테스트(엔티티↔노드, 속성↔엣지).
- 샘플 사건 1건 적재 → 사건→증거 전개(교차도메인), 공유 자원(공범) 재현 확인.

## 3. 실행 로드맵

```
P1 DDL 반영(DA)  ──▶  P2 매핑 확정  ──▶  P3 적재 파이프라인  ──▶  P4 검증
  요청 2건            엔티티·엣지         기존 재사용            정합·샘플
  [DA 의존]           [DB 무관]          [운영 DB]              [운영 DB]
```

**우선순위**: ① 개인정보(주민번호 해시·표준 DDL 준수) → ② 대표·역할 관계화(P1+P2) → ③ 나머지 속성.

## 4. 기대 효과 (2차년도 실데이터 근거)

| 효과 | 근거 |
|---|---|
| **교차 도메인 전개** | 사건 1건 → 증거 29개 즉시 연결 |
| **공유 자원·공범 탐지** | 동일 전화·IP를 쓰는 복수 주체 → 엣지 수렴 |
| **자금세탁 추적** | 계좌→계좌→가상자산(exchanged_to) 경로 |
| **시간축 분석** | v4.6 valid_from/to (개통·개설·접속) |

## 5. 리스크 · 고려사항

- **개인정보**: 주민번호는 반드시 표준 DDL 방식(해시+암호화) 준수 — 원본 PPTX의 직접 PK 지양.
- **DA 의존**: P1(DDL 2건)이 선행 — 회신 전까지 P2(매핑)는 병행 가능.
- **코드값 정합**: `ROLE_CD`·`ID_TYP_CD` 표준값을 DA에서 받아 온톨로지 매핑에 반영.
