## 용도 1 — Text2Cypher LLM 모델 파인튜닝

### 1.1 목적
자연어 수사 질의를 CCOP 온톨로지(V4.7, 노드 25종·엣지 72종) 기반 Cypher로 변환하는 **폐쇄망 배포용 소형 LLM**(7B급)을 자체 학습한다. 상용 API(GPT-4o)는 경찰 폐쇄망에서 사용 불가하므로, 온프레미스 서빙 가능한 자체 모델이 과제의 필수 산출물이다.

### 1.2 학습 방법 (본 서버 검증 레시피, 2026-08-13 확립)
| 항목 | 내용 |
|---|---|
| 베이스 모델 | **Qwen2.5-Coder-7B-Instruct** (코드/Cypher 생성 강점으로 선정) |
| 기법 | **LoRA** (r=32, α=64) — 전체 파라미터 대비 어댑터만 학습해 GPU·시간 절약 |
| 정밀도 | **bf16** (A100 80GB라 양자화 불필요 — bitsandbytes 미사용으로 호환성 리스크 제거) |
| GPU 사용 | **단일 GPU**(A100 1장)로 충분 — 나머지 1장은 서빙 유지용 |
| 프레임워크 | LLaMA-Factory + 전용 venv(`lf_venv3`: torch 2.3.1+cu121, transformers 4.44) |
| 운영 수칙 | 장시간 작업은 **setsid 필수**(SSH 세션 종료에도 학습 유지) |

### 1.3 학습 데이터 — "실행 검증" 방식 (v4.7, SynthCypher grounding)
GPT 증강 시드에 의존하던 기존(v37~v39) 방식과 달리, **실제 그래프 DB에서 실행해 결과가 나오는 쿼리만 채택**하는 방식으로 전환:
1. 실그래프에서 스키마 인벤토리 추출(실존 26경로 + 실값 샘플)
2. 한국어 질문 유형 분류(조회/역방향/집계/ip_role·국가 필터/070/자금흐름/2-hop) × 패러프레이즈 생성
3. 네이티브 Cypher 생성 → **로컬 그래프 실행 검증**(결과 0건 쿼리 폐기)
4. 최종 **645건** (graph45 568 + pierce_demo 77), train 581 / eval 64

→ 이 방식으로 "온톨로지에는 있으나 실데이터에 없는 경로를 생성하는 환각"(시연에서 발견된 `access_via` 오류)을 **데이터 소스 단계에서 차단**.

### 1.4 실측 결과 (2026-08-13, 본 서버)
- 학습 시간: **650초**(약 11분, 6 epoch) — A100 단일 GPU
- 수렴: train_loss **0.019** / eval_loss **0.016**
- 산출: LoRA 어댑터 323MB (`~/ccop_train/output/qwen25_coder_t2c_v47/final`)
- 추론 검증 **6/6 정확**: 070 필터·IP접속 역방향(시연 실패 케이스 해결)·`ip_role='call_center'`·통화관계·집계 top10·조직 소속

## 용도 2 — 학습된 LLM 모델 서빙

### 2.1 서빙 구성 (vLLM, 상시 기동)
| 포트 | 모델 | GPU | 용도 |
|---|---|---|---|
| **8004** | Qwen2.5-Coder-7B-Instruct + **v47 LoRA 어댑터** (served name `qwen25-coder-t2c-v47`) | GPU0 | **Text2Cypher 본선** — CCOP 앱이 사용 |
| 8001 | gpt-oss-20b | GPU1 | 범용 LLM 비교·보조 |
| 8003 | Qwen3-Embedding-8B (dim 4096) | GPU1 | 법률 RAG v2 / GraphRAG 임베딩 |

### 2.2 v47 서빙 레시피 (본 서버 검증, 2026-08-13 확립 · 08-25 재현)
```bash
setsid nohup env CUDA_VISIBLE_DEVICES=0 ~/vllm-serving/.venv/bin/vllm serve \
  Qwen/Qwen2.5-Coder-7B-Instruct \
  --enable-lora --max-lora-rank 32 \            # r32 어댑터: vLLM 기본 16 초과라 명시 필수
  --lora-modules qwen25-coder-t2c-v47=~/ccop_train/output/qwen25_coder_t2c_v47/final \
  --served-model-name qwen25-coder-t2c-v47 \
  --host 0.0.0.0 --port 8004 \
  --dtype bfloat16 --max-model-len 8192 \       # 문서추출 등 긴 응답 워크로드 시 8192
  --gpu-memory-utilization 0.5 > vllm_v47.log 2>&1 &
```
- vLLM 0.19.1(`~/vllm-serving/.venv`), 부팅 약 2~4분(가중치 로드+torch.compile), 점유 약 **16GB/80GB** — 학습과 서빙을 GPU 분리로 동시 운용 가능
- **LoRA 어댑터 서빙** 방식: 베이스는 공유하고 어댑터만 교체 → 버전 교체(v46→v47) 시 재배포 비용 최소
- 베이스 모델 병합(merge) 없이도 서빙 가능함을 실증 — 스토리지·기동시간 절약

### 2.3 앱 연동 구조
```
CCOP 앱(로컬/폐쇄망) ── SSH 터널(로컬 8002 → 서버 8004) ──> vLLM
  .env: SLLM_ENDPOINT=http://localhost:8002/v1
        SLLM_MODEL_NAME=qwen25-coder-t2c-v47
```
- 앱 호출 시 **학습 시 system prompt와 동일한 프롬프트**를 사용해야 함(`prompts/t2c_v47_system.txt`) — 불일치 시 일반 Cypher로 회귀하는 현상을 실측으로 확인, 코드에 프롬프트 파일 우선 로드로 고정
- sLLM 장애 시 GPT-4o 자동 폴백 경로 유지(가용성) — 폐쇄망 배포 시 폴백 없이 단독 동작

## 용도 3 — GDB 시각화 프로그램 연동 자연어→Cypher 변환 성능 테스트

### 3.1 테스트 대상 경로 (end-to-end)
```
[CCOP 웹 UI] 자연어 질문
   → LangGraph 에이전트(의도 라우팅 → v47 호출 → Cypher 생성)
   → 검증·재시도 루프(문법/스키마 사전검증, 실패 시 재생성)
   → AgensGraph 실행 (tccop_graph 계열)
   → Cytoscape.js 그래프 시각화 렌더링
```
단순 "쿼리 문자열 일치"가 아니라 **실행 결과와 화면 표시까지** 확인하는 실행 기반 평가.

### 3.2 평가 체계와 실측 수치
| 평가 | 내용 | 실측 |
|---|---|---|
| **232문항 표준 벤치마크** | 단일노드/1-hop/체인/집계/guard 등 카테고리별 회귀 평가 하네스 | 운영 표준 v42+Router **86.6%**(201/232) · v46 **88.8%**(회귀 0) · v47용 하네스 구축 완료 |
| **실행 검증** | 생성 Cypher를 실그래프에 실행, 결과 유무·정확성 판정 | v47 추론 **6/6** 정확 |
| **앱 통합 검증** | UI에서 자연어 → 시각화까지 | **3/3** 통과 — 특히 "IP 접속" 질의가 27건 정상 반환(기존 범용 모델은 `access_via` 환각으로 0건이던 시연 실패 케이스 해결) |
| **응답 시간** | UI 질의 → 시각화 e2e | 평균 약 1.3~1.4초(수사 질의 기준, 폐쇄망 요건 충족) |
| **시나리오 시연** | 2차년도 EP1~10 수사 질문을 실데이터 그래프로 검증 | 10개 에피소드 전 단계 질의·시각화 시연 완료(기술운영위 자료) |

### 3.3 이 테스트가 본 서버에서 수행되어야 하는 이유
- 성능 수치는 **서빙 환경(vLLM·GPU)과 동일 조건**에서 측정해야 배포 예측력이 있음 — 학습 서버≠서빙 서버면 회귀 원인 분리가 불가
- 벤치마크는 모델 교체(v42→v46→v47) 때마다 **회귀 평가**로 반복 실행 — 232문항 × 재시도 루프는 GPU 서빙 처리량 필요
- 폐쇄망 이식(경찰청 내부망 RTX6000Ada 서버) 전 **리허설 환경** 역할: 동일 레시피(vLLM LoRA 서빙)를 USB 이식 절차로 옮기는 것이 방문설치 계획의 전제

## 운영 수칙 요약 (실측으로 확립된 함정 회피)
1. 장시간 프로세스(학습·서빙)는 **setsid** — SSH 끊김에도 유지
2. LoRA r=32 서빙 시 `--max-lora-rank 32` 명시(vLLM 기본 16)
3. 추론 system prompt = **학습 프롬프트와 동일 파일** 사용
4. 워크스페이스 중지 시 터널 호스트가 닫힘 — 재시작 후 서빙 재기동(§2.2) + 터널 재개설 필요
5. GPU 배분: GPU0 = T2C 서빙(+학습 시 임시 전용), GPU1 = 임베딩·보조 모델
