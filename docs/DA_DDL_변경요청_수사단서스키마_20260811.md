# [DA팀 요청] 수사단서 연관관계 스키마 검토에 따른 표준 DDL 반영 요청

> **수신**: DA팀
> **발신**: SKAI (ian.kwon@skaiworldwide.co.kr)
> **일자**: 2026-08-11
> **대상 산출물**: `수사단서 연관관계분석 스키마_20260810.pptx`
> **대조 기준**: 표준 DDL `CYBERCOP_STANDARD_TABLE_DDL_20260804.sql` · CCOP v4.6 온톨로지
> **핵심 요약**: 수사단서 스키마 검토에서 5개 보완을 도출했으나, **표준 DDL을 대조한 결과 4개는 이미 반영**되어 있었습니다. **실제 DDL 변경 요청은 2건**(② 법인 대표자 관계 신설, ⑤ 직업 컬럼 추가)입니다.

---

## 1. 배경

수사 실무 스키마(PPTX)를 CCOP v4.6 온톨로지와 정합 검토하여 5개 보완 항목을 도출했습니다. 이를 표준 DDL(2026-08-04)에 반영하기 위해 대조한 결과, **표준 DDL이 이미 대부분을 반영**하고 있음을 확인했습니다. 본 문서는 그 대조 결과와 **실제로 필요한 변경 2건**을 정리합니다.

## 2. 표준 DDL 대조 결과 — 요약

| 검토 항목 | 표준 DDL 상태 | 근거 컬럼/테이블 | 조치 |
|---|---|---|---|
| ① 식별자 개인정보 | **이미 반영** | `TB_PSN_M.RRNO_HASH_VL`·`RRNO_ENCPT_VL`, `TB_INST_M.INST_ID`(PK)+`BRNO` | 변경 불필요 ✅ |
| ③ 사건–인물 역할 | **이미 반영** | `TB_INCDNT_PSN_REL_T.ROLE_CD`(역할코드) | 변경 불필요 ✅ |
| ④ 닉네임 / SNS 통합 | **이미 반영** | `TB_DGTL_ID_M.ID_TYP_CD`·`PLFM_NM`·`RLNM_VL` | 변경 불필요 ✅ |
| ⑤ 속성 — 개통일 | **이미 반영** | `TB_TELNO_JOIN_T.JOIN_DT`(가입일시)·`CNCLTN_DT`(해지일시) | 매핑만 |
| ⑤ 속성 — 직업 | **미반영** | `TB_PSN_M`에 직업 컬럼 없음 | **추가 요청 (2)** |
| ② 법인 대표 | **미반영** | `TB_INST_M`에 대표 컬럼·관계 없음 | **신설 요청 (1)** |

> **결론**: 표준 DDL은 개인정보(해시+암호화)·역할·ID타입을 이미 견고하게 반영하고 있습니다. 오히려 원본 PPTX(주민번호 직접 PK 등)가 표준 DDL을 따르도록 권고합니다. 신규 변경은 아래 2건으로 최소화됩니다.

---

## 3. 변경 요청 (2건)

### 요청 1 (필수) — 법인 대표자 관계 신설

**현황**: `TB_INST_M`(기관기본)에 대표자 컬럼이 없고, 기관–인물 대표 관계 테이블도 부재. 현재 법인 대표를 정규화된 형태로 저장할 수 없습니다.

**요청**: 기관–대표자 관계 테이블 신설(권고) 또는 `TB_INST_M` 대표 FK 추가.

```sql
-- 권고안: 관계 테이블 신설 (다대다·이력 대응 → 같은 대표의 여러 법인 탐지)
CREATE TABLE TB_INST_RPRS_REL_T
(
    REL_SN        BIGSERIAL NOT NULL,
    INST_ID       varchar(200) NOT NULL,   -- 기관(법인) FK → TB_INST_M
    PSN_ID        varchar(200) NOT NULL,   -- 대표 인물 FK → TB_PSN_M
    RPRS_SE_CD    varchar(20),             -- 대표구분코드(대표이사/사내이사 등)
    VALID_FROM    date,                    -- 대표 재임 시작(유효구간)
    VALID_TO      date,                    -- 대표 재임 종료
    SRC_ID        varchar(50),
    CRT_DT        timestamp with time zone DEFAULT CURRENT_TIMESTAMP NOT NULL
);
COMMENT ON TABLE  TB_INST_RPRS_REL_T IS '기관대표자관계';
COMMENT ON COLUMN TB_INST_RPRS_REL_T.INST_ID IS '기관아이디';
COMMENT ON COLUMN TB_INST_RPRS_REL_T.PSN_ID  IS '대표사람아이디';
COMMENT ON COLUMN TB_INST_RPRS_REL_T.RPRS_SE_CD IS '대표구분코드';

-- 대안(단순): TB_INST_M 에 대표 FK 단일 컬럼
-- ALTER TABLE TB_INST_M ADD COLUMN RPRS_PSN_ID varchar(200);
-- COMMENT ON COLUMN TB_INST_M.RPRS_PSN_ID IS '대표사람아이디';
```

**사유**: 대표를 문자열 속성이 아닌 **관계**로 두면, 동일 대표가 다수 법인을 지배하는 구조(바지사장·연결고리)를 즉시 탐지할 수 있습니다. `VALID_FROM/TO`는 CCOP v4.6 유효구간과 정합.

---

### 요청 2 (권고) — 개인 직업 컬럼 추가

**현황**: `TB_PSN_M`(사람기본)에 직업 컬럼 없음. PPTX 수사 스키마에는 '직업'이 명시되어 있으나 표준 DDL에 대응 컬럼이 없습니다.

```sql
ALTER TABLE TB_PSN_M ADD COLUMN OCCP_NM varchar(100);   -- 직업명
COMMENT ON COLUMN TB_PSN_M.OCCP_NM IS '직업명';
-- 코드 관리 시: OCCP_CD varchar(20) 병행 (GNDR_CD·NTNLTY_CD 스타일 일관)
```

**사유**: 수사 프로파일의 기본 속성. 나이는 기존 `BRDT`(생년월일)로 유도 가능하므로 별도 불필요.

---

## 4. 이미 반영된 항목 — 확인 (변경 불필요)

표준 DDL이 아래를 이미 잘 반영하고 있어 **추가 조치가 필요 없습니다**. PPTX 원본이 이 표준을 따르도록 하는 것이 바람직합니다.

| 항목 | 표준 DDL |
|---|---|
| 주민등록번호 | `TB_PSN_M.RRNO_HASH_VL`(해시) + `RRNO_ENCPT_VL`(암호화) — 직접 PK 아님, 개인정보보호 정합 |
| 사업자번호 | `TB_INST_M.INST_ID`(대리키 PK) + `BRNO`(속성) |
| 사건–인물 역할 | `TB_INCDNT_PSN_REL_T.ROLE_CD`(역할코드) — 피의자/피해자/참고인 코드로 구분 |
| SNS/닉네임 | `TB_DGTL_ID_M.ID_TYP_CD`(타입) + `PLFM_NM`(플랫폼) + `RLNM_VL`(실명) |
| 전화 개통/해지 | `TB_TELNO_JOIN_T.JOIN_DT`(가입일시) + `CNCLTN_DT`(해지일시) — v4.6 valid_from/to 로 매핑 |

---

## 5. 요청 사항

1. **요청 1(법인 대표자 관계)** — 신설 여부 및 방식(관계 테이블 vs FK) 회신
2. **요청 2(직업 컬럼)** — `TB_PSN_M.OCCP_NM` 추가 검토
3. **매핑 확인** — 전화 개통/해지일(`JOIN_DT`/`CNCLTN_DT`)을 CCOP `valid_from/to`로 매핑하는 데 이견 없는지 확인
4. 역할코드(`ROLE_CD`)·ID타입코드(`ID_TYP_CD`)의 **코드값 정의서**가 있으면 공유 요청 (수사 역할/ID 유형 표준값 정합용)
