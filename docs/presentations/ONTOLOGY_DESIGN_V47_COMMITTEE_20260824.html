01
온톨로지 개요

온톨로지란 — 수사 데이터를 그리는 "공통 설계도"

수사에 등장하는 대상을 점(노드)으로, 관계를 선(엣지)으로 — 무엇을 어떻게 그릴지 미리 정한 표준 규칙집

예시 — "피의자 A가 자기 계좌에서 다른 계좌로 돈을 보냈다"는 한 문장이 아래 그림이 됩니다:

사건
중고거래 사기 suspect_in←피의자 피의자 A has_account→계좌 소유 계좌 ①
110-222-333 from_account→출금 이체
3/5 14:02 · 500만원 to_account→입금 계좌 ②
  • 수사에 나오는 대상 25종류(인물·계좌·전화·IP·사건 등)와 관계 72종류(소유·이체·통화·공범 등)를 미리 정의
  • 정의에 없는 연결은 시스템이 "말이 안 되는 연결"로 자동 거부 — AI가 지어낸 오류(환각)를 걸러내는 기준
  • 같은 데이터라면 누가 만들어도 같은 그래프 — 사건 간 비교·통합 가능
  • "이 계좌와 연결된 사람은?"을 자연어로 물으면 자동 조회 — AI가 설계도를 보고 질의문을 만들기 때문

설계도가 없으면 자동화도 없다 — 온톨로지는 문서가 아니라 시스템 네 곳이 실시간 참조하는 동작 규칙이다

기존 방식과 무엇이 다른가

기존 — 분석가가 손으로 그림
  • 해외 상용도구(i2 등)는 분석가가 문서를 읽고 마우스로 점과 선을 직접 그림

04
핵심 설계 원칙 ①

전화·계좌·IP는 "메모"가 아니라 "점"으로 그린다

이렇게 하면 안 되는 이유

인물 카드에 메모처럼 붙이는 방식

가입자 A 카드: IP: 122.54.197.65, …
가입자 B 카드: IP: 122.54.197.65, …

→ 두 카드에 같은 IP가 적혀 있어도 아무도 모릅니다. 카드를 일일이 펼쳐 눈으로 대조해야만 발견되는 정보가 됩니다.

  • 전화번호는 통화의, 계좌는 이체의 당사자 — 메모로 붙이면 통화망·자금흐름 선을 걸 수 없음
CCOP 방식 — 공유가 그림에서 바로 보임
가입자 A used_ip→ IP
122.54.197.65 ←used_ip 가입자 B
↑used_ip 가입자 C
  • IP가 하나의 점이 되면, 그 점에 여러 사람이 연결되는 순간 공유가 드러남
  • 실제 검증 — 2차년도 가입자 자료에서 IP 122.54.197.65 한 점이 서로 다른 문서의 3명을 연결, 조직 관계 단서를 자동 포착
  • 화면에서는 다시 "인물 중심 카드"로 보여줄 수 있음 — 저장은 분리, 표시는 편하게

05
핵심 설계 원칙 ②

"이체 한 건"도 점으로 그린다 — 행위의 노드화

예: "3월 5일 14:02, 계좌 ①에서 계좌 ②로 500만 원이 해외 IP를 거쳐 이체됐다"

이 한 건에는 시각 · 금액 · 보낸 계좌 · 받은 계좌 · 접속 IP, 다섯 가지 정보가 들어 있습니다. 계좌①→계좌② 선 하나에는 다 담을 수 없어, "이체"라는 점을 만들고 관련된 것들을 연결합니다:

계좌 ①
보낸 쪽 from_account→ 이체
3/5 14:02 · 500만원 to_account→ 계좌 ②
받은 쪽 via_ip→ 접속 IP
어디서 보냈나
  • 통화·접속·메시지·이동·사칭도 같은 방식 — "언제·얼마나·어떻게"가 붙는 행위는 전부 점
  • 디지털 증거 국제 표준(CASE)과 같은 방식 — 증거로서의 상세를 잃지 않음
  • 빠른 추적용 지름길도 함께 유지 — 계좌①→계좌② 요약 선(transferred_to)을 병행: "돈이 어디까지 흘러갔나"를 3~4단계씩 쫓을 때는 지름길이 빠름
  • 즉, 상세는 이체 점에서, 흐름 추적은 요약 선에서 — 두 표현을 용도별로 사용

핵심 설계 원칙 ③

시간을 기록한다 — "언제 있었던 일인가"와 "언제 알았는가"

부동산 등기부처럼, 모든 관계에 "언제부터 언제까지"를 기록 (bitemporal)

왜 두 가지 시간이 필요한가 — 2017년 통신기록을 2026년에 영장으로 입수했다면: 사실이 있었던 때는 2017년(유효 시간), 우리가 알게 된 때는 2026년(기록 시간). 둘을 나눠 적어야 "그 시점에 무슨 일이 있었나"와 "이 판단의 근거는 언제 확보됐나"를 모두 답할 수 있습니다.

실제 사례 — IP 27.193.61.154 (2차년도 데이터)

2017년 3월 · 3명이 함께 사용 → 2017년 4월 · 1명이 단독 사용

시간 없이 통째로 판정하면 이 IP는 그냥 "공유 IP"가 됩니다. 그 순간 4월의 단독 사용 — 특정 인물을 좁힐 수 있는 단서 — 가 사라집니다.

V4.6에서 반영한 것

  • "누가 이 IP를 썼다"는 연결에 사용 기간을 기록 — 접속기록의 처음~마지막 시각으로 자동 산출
  • IP의 성격(단독/공유/콜센터급/호스팅)을 기간별로 판정해 이력으로 보관 — 실데이터 모의 적용에서 성격이 바뀐 IP 127개 검출
  • 새로 가능해진 질문: "2017년 3월 15일에 이 IP를 쓴 사람은?" · "성격이 바뀐 IP 전부 보여줘" (역할 전환은 조직 재편의 신호)
  • 관계 종류는 하나도 안 늘림(속성만 추가) → 질의 AI 재학습 불필요, 기존 화면도 그대로 동작
