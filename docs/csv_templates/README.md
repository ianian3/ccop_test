# CCOP 온톨로지 적재용 CSV 규격서 (전처리 기관 배포용)

> **문서 목적**: 전처리 기관이 RAW 데이터를 CCOP 플랫폼에 업로드 가능한 형태로 가공하기 위한 파일·컬럼 규격.
> **적용 기준**: skai2_vm 운영 컨테이너 현행 코드 (`import_predefined_schema_to_rdb` + `transfer_data`).
> **검증 상태**: ✅ 2026-08-27 운영 환경 격리 스키마에서 9종 전량 시범 적재·그래프 변환 검증 완료.
> **동봉 파일**: 본 문서와 같은 폴더의 샘플 CSV 9개 (`tbl_*.csv`).

---

## 1. 한눈에 보기

전처리 기관은 아래 **3가지만** 규격에 맞추면 됩니다.

1. **파일명** — `tbl_`로 시작 + 정해진 키워드 포함
2. **헤더(첫 행)** — 규격 컬럼명과 철자·대소문자까지 정확히 일치
3. **값 형식** — 날짜/시간, 입출금 구분 등 정해진 표기

값의 코드 변환(은행코드·통신사코드 등)이나 온톨로지 매핑은 **플랫폼이 자동 처리**하므로 기관에서 할 필요가 없습니다.

### 적재 흐름

```
규격 CSV 업로드  →  표준 테이블(test_v40) 자동 적재  →  KICS 온톨로지 그래프 생성  →  수사 그래프 조회·분석
```

## 2. 공통 규칙 (모든 파일 공통)

| 항목 | 규칙 |
|------|------|
| **파일명** | 반드시 `tbl_`로 시작하고, 각 파일의 **키워드**를 그대로 포함. 뒤에 사건번호·날짜 등 자유 추가 가능.<br>예: `tbl_vt_psn_2026사건.csv` (O) / `인물목록.csv` (X — 그래프 미반영) |
| **키워드 혼용 금지** | 파일명은 키워드로 인식되므로, **한 파일명에 서로 다른 키워드를 섞지 말 것** (예: `tbl_eg_case_prsn`은 `case_prsn`으로만 인식). |
| **헤더** | 첫 행은 헤더. 컬럼명은 규격과 **정확히 일치**. 규격에 없는 컬럼은 무시, 필수 컬럼이 비면 해당 행 제외. |
| **인코딩** | **UTF-8** 저장 (Excel의 "CSV UTF-8" 저장 = BOM 포함, 그대로 허용). 구분자는 쉼표(`,`). |
| **쉼표가 든 값** | 값 안에 쉼표가 있으면 해당 칸을 큰따옴표(`"`)로 감쌀 것. |
| **업로드 순서** | **노드 파일(`tbl_vt_*`) 먼저 → 관계·이벤트 파일(`tbl_eg_*`) 나중**. 관계 파일이 참조하는 노드가 함께 있어야 연결됨. |

> ⚠️ **초기화 주의**: 플랫폼 업로드 시 기본 옵션(fresh)은 **첫 파일 적재 직전 스테이징을 전체 초기화**합니다. 한 건의 데이터셋은 **한 번에 묶어서** 업로드하세요.

## 5. 반드시 확인할 주의사항 (검증으로 실증됨)

1. **인물은 "이름"으로만 식별됩니다.**
   인물 노드와 모든 관계 파일에서 같은 사람은 **완전히 동일한 이름 문자열**이어야 합니다. 띄어쓰기·오탈자가 다르면 다른 사람으로 갈라지고, 동명이인은 한 명으로 합쳐집니다. → **사전에 이름 정제·통일 필요.**

2. **계좌는 "계좌번호"로만 식별됩니다.**
   적재 시 은행코드가 일괄 고정값(`999`)으로 저장되므로, **은행이 달라도 계좌번호가 같으면 한 노드로 합쳐집니다.** → 계좌번호 표기(하이픈 포함/제거)를 **기관 내부에서 하나로 통일**하세요.

3. **날짜·시간 형식을 지켜야 합니다.**
   통화(`bgng_ymdhm`·`end_ymdhm`)·이체(`rmt_ymdhm`)는 `YYYY-MM-DD HH:MM:SS`, 사건 발생일(`occrn_dt`)은 `YYYY-MM-DD`. 형식이 어긋나면 통화시간이 0으로 계산되거나 값이 누락됩니다. (검증: `14:22:05→14:24:37` = 152초 정상 계산 확인)

4. **금액은 쉼표를 허용합니다.**
   `1,500,000` 형태로 넣어도 자동으로 숫자 처리됩니다.

5. **인물 노드는 자동 익명화될 수 있습니다.**
   그래프 후처리 단계에서 인물명 익명화가 적용되므로, 실데이터 적재 시 **이름 표시 정책을 플랫폼 담당자와 사전 확인**하세요.

## 6. 납품 전 체크리스트

- [ ] 모든 파일명이 `tbl_`로 시작하고 규격 키워드를 포함한다
- [ ] 한 파일명에 서로 다른 키워드를 섞지 않았다
- [ ] 첫 행 헤더가 규격 컬럼명과 철자·대소문자까지 일치한다
- [ ] 필수 컬럼(★)에 빈 값이 없다
- [ ] 같은 인물은 모든 파일에서 동일한 이름으로 표기했다
- [ ] 계좌번호 표기 방식을 하나로 통일했다
- [ ] 날짜·시간이 규정 형식(`YYYY-MM-DD HH:MM:SS`)을 따른다
- [ ] 금액에 문자(원 등)를 넣지 않았다 (쉼표는 허용)
- [ ] 파일을 UTF-8로 저장했다
- [ ] 관계 파일이 참조하는 노드가 노드 파일에 함께 포함돼 있다
- [ ] 한 데이터셋을 한 번에 묶어서 업로드할 준비가 됐다

## 8. 참고 소스 코드 (`reference_loader.py`)

규격 CSV가 표준 테이블에 어떻게 적재되는지 직접 확인·검증하실 수 있도록, CCOP 플랫폼 적재 로직의 **참고 구현**을 동봉합니다. 컬럼 매핑·식별키·정규화·이체방향 판정 로직이 운영과 동일합니다.

```bash
# 의존성
pip install pandas psycopg2-binary

# 실행 (tbl_*.csv 가 있는 폴더에서, 권장 순서로 자동 적재)
python reference_loader.py \
    --dsn "host=<HOST> port=<PORT> dbname=<DB> user=<USER> password=<PW>" \
    --schema test_ccop \
    --dir ./
```

- `--fresh` 옵션을 주면 첫 파일 적재 전에 대상 스키마를 초기화합니다.
- 대상 스키마에는 표준 테이블(`tb_prsn`, `tb_fin_bacnt`, `tb_telno_mst`, `tb_telno_call_dtl`, `tb_fin_bacnt_dlng`, `tb_fin_extrc_bacnt`, `tb_telno_join`, `tb_incdnt_mst`)이 미리 있어야 합니다. `tb_incdnt_prsn`은 스크립트가 자동 생성합니다.
- 표준 테이블 적재 이후의 온톨로지 그래프 변환은 CCOP 플랫폼 내부 단계이며 본 참고 코드 범위 밖입니다.

> 본 코드는 CCOP 플랫폼 참고용 발췌본입니다. 협력 범위 내 참고 용도로만 사용해 주세요.
