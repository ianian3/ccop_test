# DA 확인 요청 · `TB_INCDNT_M.FLNM` 의미 (성명 vs 사건관리번호) (2026-09-28)

> **상태**: 초안 — 발송 전 검토용
> **참조**: `CYBERCOP_STANDARD_TABLE_DDL_20260911.sql` · `6. CCOP-DE53-테이블명세서_20260911_v0.9.6(SKAI).xlsx` ·
> `01_CYBERCOP_신규표준용어목록_20260602.xlsx` · `RDB_STANDARDIZATION_v3.6.md`(표준 DDL 참고문서)
> **결론 한 줄**: `TB_INCDNT_M.FLNM` 이 **'성명'** 으로 정의돼 있으나 CCOP 에서는 **내부 사건관리번호(파일번호)** 로
> 써 온 컬럼입니다. 의도 확인과, 사건관리번호용 표준용어·컬럼명 확정을 요청드립니다.

---

## 1. 요청 요지

1. `TB_INCDNT_M.FLNM` 의 의미가 **성명**인지, **사건관리번호(파일번호)** 인지 확인 부탁드립니다.
2. 사건관리번호라면 이를 담을 **표준용어·컬럼명 확정**을 요청드립니다 (현재 사전에 해당 용어 없음).
3. 표준용어목록의 `FLNM` 항목 **영문명 불일치**(아래 2-③) 정정 여부 확인 부탁드립니다.

---

## 2. 확인 근거

### ① 표준 DDL · 테이블명세서 — '성명'

```sql
-- CYBERCOP_STANDARD_TABLE_DDL_20260911.sql (147행~)
CREATE TABLE TB_INCDNT_M
(
    INCDNT_NO    varchar(20) NOT NULL,
    FLNM    varchar(50),
    INCDNT_NM    varchar(300) NOT NULL,
    ...
COMMENT ON COLUMN TB_INCDNT_M.INCDNT_NO IS '사건번호';
COMMENT ON COLUMN TB_INCDNT_M.FLNM IS '성명';        -- 177행
COMMENT ON COLUMN TB_INCDNT_M.INCDNT_NM IS '사건명';
```

- 테이블명세서 v0.9 ~ v0.9.6(0911) 컬럼정의서 모두 `TB_INCDNT_M | FLNM | 성명 | varchar(50)`.
- 같은 DDL 의 사람 성명은 `TB_PSN_M.KORN_FLNM`('한글성명')으로 따로 있습니다. 사건기본 테이블에 성명 컬럼이 있는
  이유(누구의 성명인지)가 명세에 없습니다.

### ② 표준 DDL 의 참고문서(설계서 v3.6) · CCOP 기준 — '내부 사건번호'

```sql
-- RDB_STANDARDIZATION_v3.6.md (표준 DDL 헤더가 참고문서로 명시)
CREATE TABLE TB_INCDNT_MST (
    INCDNT_NO       VARCHAR(20)     NOT NULL,   -- 사건번호 (경찰청 공식)
    FLNM            VARCHAR(50)     NULL,       -- CCOP 내부 사건번호
    INCDNT_NM       VARCHAR(300)    NOT NULL,   -- 사건명
-- Graph Bridge Key: vt_case.flnm → TB_INCDNT_MST.FLNM
```

| 문서 | `FLNM` 정의 |
|---|---|
| 설계서 v3.6 / CCOP RDB DDL v3.2 | CCOP 내부 사건번호 |
| KICS 기반 표준화 가이드 (2026-01) | 사건관리번호 (예: `2026-000123`) |
| 협력기관 데이터 표준 | 사건번호 |
| **표준 DDL 20260804 · 20260911 / 명세서 v0.9.x** | **성명** |

→ 컬럼 구성(`INCDNT_NO` · `FLNM varchar(50)` · `INCDNT_NM`)은 참고문서와 동일하고 **주석만 바뀌었습니다.**

### ③ 표준용어목록 — 한글명과 영문명이 서로 다름

```
01_CYBERCOP_신규표준용어목록_20260602.xlsx
표준용어명 | 영문명     | 영문약어명 | 용어설명 | 표준도메인 | 제정일자
성명       | File Name  | FLNM      | 성명     | 명V50     | 20260604
```

- 한글명 **'성명'** 과 영문명 **'File Name'** 이 다른 개념입니다.
- 공통표준용어 관례상 `FLNM` = 성명(Full Name)이고(`KORN_FLNM`=한글성명과 일관), 파일 계열 용어는
  `FILE_` 접두(`FILE_SHA256_HASH_VL`, `FILE_SZ_BYTE_CNT`)를 씁니다.
- 추정: CCOP 레거시 컬럼 `FLNM`(내부 사건번호/파일번호)을 등록하는 과정에서 약어가 공통표준 '성명'과 겹쳐
  한글명이 '성명'으로 들어간 것으로 보입니다. **확인 부탁드립니다.**

## 3. 제안 (DA 판단 요청)

| 안 | 내용 | 평가 |
|---|---|---|
| **A (권장)** | 사건관리번호용 **신규 표준용어 등록 + 컬럼명 변경**. 예) 표준용어 `사건관리번호` / Incident Management Number / `INCDNT_MNG_NO` / 번호V50 (관례: `ATM_MNG_NO`=ATM관리번호). `TB_INCDNT_M.FLNM` → `INCDNT_MNG_NO`. 표준용어 `성명`의 영문명은 `Full Name` 으로 정정 | `FLNM`=성명 표준 체계를 유지하면서 혼동 제거 |
| B | 컬럼명 `FLNM` 유지, 주석만 '사건관리번호'로 정정 | 변경량 최소. 단 표준용어 `FLNM`(=성명)과 충돌이 남음 |
| C | `FLNM` = 성명이 맞음 (사건 관련 인물 성명 등 별도 의도) | 이 경우 **누구의 성명인지** 명시 요청 + 사건관리번호 컬럼 별도 신설 필요 |

※ 영문명·약어·도메인은 DA 표준용어 규칙에 맞춰 최종 확정 요청드립니다. "사건관리번호"와 "파일번호" 중 어느 용어로
등록할지도 함께 정해 주시면 됩니다.

## 4. 당사 측 영향 (참고)

분리해 쓰고 있습니다 (온톨로지 V4.8, 2026-09-18 적용). DA 확정 후 아래를 맞춥니다.

- RDB 적재(`TB_INCDNT_M`)의 사건관리번호 컬럼명 · 사건명(`INCDNT_NM`) 적재 경로
- 그래프 속성명 (`vt_case.flnm` 유지 또는 표준 약어로 개명) 및 협력기관 CSV 규격 `tbl_eg_case.flnm`
- 온톨로지 전달본(Python·XLSX) 속성 사전

회신 요청: 1·2·3 각 항목에 대한 확인 결과 (A/B/C 중 선택, 확정 용어·컬럼명).
