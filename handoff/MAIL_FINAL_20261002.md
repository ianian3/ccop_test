```
1. 인물 관리번호(psn_id / prsn_id) — 가능하면 채워 주십시오

당사 적재기가 인물을 관리번호로 식별하도록 바뀌었습니다.

 - 인물 파일(tbl_vt_psn)의 psn_id와 관계 파일(tbl_eg_bactno_poss, tbl_eg_telno_poss, tbl_eg_case_prsn)의
   prsn_id에 같은 값을 넣어 주십시오. 관리번호가 있으면 동명이인이 정확히 분리됩니다.
 - 관리번호가 없으면 종전처럼 이름(flnm)으로 연결합니다. 이때 이름은 모든 파일에서 완전히 같은
   문자열이어야 합니다. 같은 납품 안에 동명이인이 있으면 이름만으로는 누구인지 정할 수 없어 그 행이
   연결되지 않으니, 이 경우에는 관리번호가 꼭 필요합니다.
 - 관리번호는 귀 기관 안에서 일관되기만 하면 됩니다. 다만 다른 기관 번호와 겹칠 수 있는 형식
   (예: P-0001)이라면 기관 접두어를 붙여 주시면(예: ETRI-P-0001) 안전합니다.


2. 계정 플랫폼(platform) — 채워 주십시오

계정은 이제 (플랫폼, 아이디) 쌍으로 구분합니다. 카카오 abc와 네이버 abc는 서로 다른 계정이 됩니다.

 - tbl_eg_id_use의 platform, tbl_eg_id_msg의 snd_platform·rcv_platform을 채워 주십시오.
 - IP·위치 사용 파일(tbl_eg_ip_use, tbl_eg_loc_use)에는 플랫폼 컬럼이 없어, 같은 아이디를 여러
   플랫폼에서 쓰는 경우 그 행은 계정과 연결되지 않습니다.


3. 납품 전 점검
```

```
○○○ 님, 안녕하십니까. 스카이월드와이드 권○○입니다.

CSV를 그래프로 변환하는 코드를 직접 구현하고 계셔서, 온톨로지 V4.9 정의와 참조 적재기 보완본을
함께 보내드립니다. 입력 CSV 규격은 V4.8 그대로이고, 바뀐 것은 그래프를 만드는 규칙입니다.


1. 반영해 주실 사항

 (1) 온톨로지 V4.9
     엣지 72종 → 52종(중복·추론 엣지 삭제, 같은 의미 통합), 이메일 노드(vt_email)를 계정(vt_id)으로 흡수,
     사건 식별자 incdnt_no, 관계의 쌍 단위 집계 규칙.
     → 상세: ontology_v4.9.zip 의 README.md 맨 앞 변경점 표

 (2) 인물 식별 키 psn_id
     psn_id가 있으면 그대로 키로 씁니다. 없으면 'psn:{기관}:{이름}'을 만들어 키로 씁니다.
     다른 기관에서 온 같은 이름의 인물은 합치지 않고 same_as 후보(review_status='pending',
     경로 탐색 제외)로 잇습니다. 가린 이름(김** 등)은 후보도 만들지 않습니다.
     → 규격서 §3.4, 정의 스펙 NODE_ID_STANDARD['vt_psn']

 (3) 계정 식별 키 (platform, id_val)
     플랫폼이 다른 같은 아이디는 다른 계정입니다. 플랫폼이 비면 'unknown', 이메일은 소문자로 맞춥니다.
     → 규격서 §3.4, 정의 스펙 NODE_ID_STANDARD['vt_id']

 (4) ATM·기관·출처 키
     정의 스펙은 ID가 없을 때 명칭 기반 전역 ID(atm:g:{명칭} 등)를 쓰도록 정합니다. 참조 적재기는
     아직 ATM을 이름(atm_nm)으로 식별하고 있어, 감사 도구에 vt_atm.atm_id 충전율 경고가 1건 나옵니다
     (위반은 아닙니다).


2. 참조 적재기에서 발견한 결함 — 귀 기관 구현도 확인 부탁드립니다

규격서는 관계 파일의 인물 컬럼을 prsn_id로 정하고 있는데, 당사 참조 적재기는 psn_id라는 이름만
읽고 있었습니다. 그래서 prsn_id만 있는 사건-인물 파일(tbl_eg_case_prsn)의 관계가 경고 없이 전부
빠졌습니다(피의자·피해자 엣지 0건). 참조 적재기를 바탕으로 구현하셨다면 같은 결함이 있을 수 있어
확인을 부탁드립니다. 보완본은 이를 고쳤습니다.


3. 검수 기준 — 동봉 예제(examples.zip)를 적재했을 때

 - 합계        : 노드 18 · 엣지 26
 - 사건-인물   : suspect_in 2건(P-2026-0001, P-2026-0002), victim_in 1건(P-2026-0003)
 - 인물 키     : vt_psn.psn_id = P-2026-0001 ~ 0003 (이름은 name 속성)
 - 계정 키     : vt_id (kakao, hong_gd88), (naver, cheolsu.k)
 - 감사        : audit_ontology_v49.py --graph <그래프명> 위반 0
                 (vt_atm.atm_id 충전율 경고 0/1은 위 1-(4) 사유로 정상)
 - 멱등        : 같은 폴더를 두 번 적재해도 노드·엣지 수 변화 없음

참조 적재기로 직접 확인하시려면:

   python3 load_csv_to_graph.py examples/ --graph ref_check --org <기관코드> --reset

 - --org는 관리번호 없이 이름만 있는 인물이 있을 때 필요합니다. 빠지면 아무것도 쓰지 않고 멈춥니다.
 - 보완 전 방식으로 만든 그래프에 덧붙이려 하면 적재기가 감지하고 --reset(새로 적재)을 안내합니다.
```
