CSV 적재 규격 V4.8 의 보완 사항을 안내드립니다. **결론부터 말씀드리면, CSV 파일 구성과 컬럼은 바뀌지 않습니다.**
지금처럼 작성해 주시면 됩니다. 다만 아래 두 컬럼을 채워 주시면 당사 그래프에서 인물·계정이 더 정확하게 구분됩니다.

**1. 인물 관리번호(`psn_id` / `prsn_id`) — 가능하면 채워 주십시오**

당사 적재기가 인물을 관리번호로 식별하도록 바뀌었습니다.
- `tbl_vt_psn` 의 `psn_id`, 관계 파일(`tbl_eg_*_poss`, `tbl_eg_case_prsn`)의 `prsn_id` 에 **같은 값**을 넣어 주십시오.
  관리번호가 있으면 동명이인이 정확히 분리됩니다.
- 관리번호가 없으면 종전처럼 이름(`flnm`)으로 연결합니다. 이때 이름은 모든 파일에서 **완전히 같은 문자열**이어야 하고,
  같은 납품 안에 동명이인이 있으면 이름만으로는 누구인지 정할 수 없어 그 행이 빠집니다 — 이 경우 관리번호가 꼭 필요합니다.
- 관리번호는 귀 기관 안에서 일관되기만 하면 됩니다. 다만 다른 기관 번호와 겹칠 수 있는 형식(예: `P-0001`)이라면
  기관 접두어를 붙여 주시면(예: `ETRI-P-0001`) 안전합니다.

**2. 계정 플랫폼(`platform`) — 채워 주십시오**

계정은 이제 (플랫폼, 아이디) 쌍으로 구분합니다. 카카오 `abc` 와 네이버 `abc` 는 다른 계정이 됩니다.
`tbl_eg_id_use`·`tbl_eg_id_msg`(`snd_platform`·`rcv_platform`)의 플랫폼을 채워 주십시오.
IP·위치 사용 파일(`tbl_eg_ip_use`·`tbl_eg_loc_use`)에서 계정을 가리킬 때는 플랫폼 컬럼이 없으므로,
같은 아이디를 여러 플랫폼에서 쓰는 경우 그 행은 연결되지 않습니다.

**3. 납품 전 점검**

종전과 같이 `python3 validate_csv_v48.py <CSV폴더>` 로 점검해 주시면 됩니다. 동봉 예제는 위반 0건입니다.

나머지는 변경이 없습니다. 이미 납품해 주신 자료는 당사가 새 방식으로 다시 적재하므로 다시 보내실 필요가 없습니다.
문의 사항은 회신 부탁드립니다.

CSV → 그래프 변환을 직접 구현하고 계셔서, 온톨로지 V4.9 정의와 함께 참조 적재기 보완본을 보내드립니다.
**입력 CSV 규격은 V4.8 그대로**이고, 바뀐 것은 그래프를 만드는 규칙입니다.

**1. 반영해 주실 사항**

| # | 항목 | 내용 | 근거 |
|---|---|---|---|
| 1 | 온톨로지 V4.9 | 엣지 72→52종(삭제·통합), `vt_email`→`vt_id` 흡수, 사건 키 `incdnt_no`, 쌍 단위 집계 규칙 | `ontology_v4.9/README.md` 변경점 표 |
| 2 | **인물 키 `psn_id`** | `psn_id` 가 있으면 그대로, 없으면 `psn:{기관}:{이름}` 생성. 다른 기관 같은 이름은 합치지 않고 `same_as` 후보(`review_status:'pending'`) | 규격서 §3.4, `NODE_ID_STANDARD['vt_psn']['synthesize']` |
| 3 | **계정 키 (`platform`, `id_val`)** | 플랫폼이 빈 값이면 `unknown`, 이메일은 소문자 | 규격서 §3.4, `NODE_ID_STANDARD['vt_id']` |
| 4 | ATM·기관·출처 키 | 스펙은 ID 가 없을 때 명칭 기반 전역 ID(`atm:g:{명칭}` 등)를 정의합니다. **참조 적재기는 아직 ATM 을 `atm_nm` 으로 식별**하므로 감사 도구에 `vt_atm.atm_id` 충전율 ⚠ 가 나옵니다(위반 아님) | `NODE_ID_STANDARD[...]['synthesize']['scope']='global'` |

**2. 참조 적재기에서 발견한 결함 — 귀 기관 구현도 확인 부탁드립니다**

규격서는 관계 파일의 인물 컬럼을 **`prsn_id`** 로 정하고 있는데, 당사 참조 적재기는 `psn_id` 라는 이름만 읽고 있었습니다.
그래서 `prsn_id` 만 있는 `tbl_eg_case_prsn`(사건-인물)의 관계가 **경고 없이 전부 빠졌습니다**(피의자·피해자 엣지 0건).
참조 적재기를 바탕으로 구현하셨다면 같은 결함이 있을 수 있습니다. 보완본은 이를 고쳤습니다.

**3. 검수 기준 — 동봉 예제(`examples.zip`)를 적재했을 때**

| 항목 | 기대값 |
|---|---|
| 합계 | 노드 18 · 엣지 26 |
| 사건-인물 | `suspect_in` 2 (P-2026-0001, P-2026-0002) · `victim_in` 1 (P-2026-0003) |
| 인물 키 | `vt_psn.psn_id` = P-2026-0001~0003 (이름은 `name` 속성) |
| 계정 키 | `vt_id` (kakao, hong_gd88) · (naver, cheolsu.k) |
| 감사 | `audit_ontology_v49.py --graph <그래프>` 위반 0 (⚠ `vt_atm.atm_id` 충전율 0/1 은 위 4번 사유로 정상) |
| 멱등 | 같은 폴더를 두 번 적재해도 노드·엣지 수 변화 없음 |

참조 적재기로 직접 확인하시려면:
```bash
python3 load_csv_to_graph.py examples/ --graph ref_check --org <기관코드> --reset
```
(`--org` 는 관리번호 없이 이름만 있는 인물이 있을 때만 필요하고, 빠지면 아무것도 쓰지 않고 멈춥니다.
보완 전 방식으로 만든 그래프에 덧붙이려 하면 감지하고 `--reset` 을 안내합니다.)
