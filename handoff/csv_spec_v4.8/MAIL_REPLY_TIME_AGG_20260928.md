# 회신 메일 초안 — 위치·IP 관계의 시각 집계 질의

> 보내기 전 확인: ①수신자 호칭 ②발신자 실명 ③질의에 나온 수치(1,207건 → 380개)가 귀 기관 자료 기준인지
> 별첨: load_csv_to_graph.py(갱신) · CCOP_CSV_적재규격_V4.8.md(§4 보완) · ontology_v4.8.zip(갱신)

○○○ 님, 안녕하십니까. 스카이월드와이드입니다.

문의 주신 위치(`evt_ymdhm`)·IP(`valid_from`) 관계 집계 건 회신드립니다.

**결론부터 말씀드리면, 관계를 하나로 합치는 것은 규격의 의도가 맞습니다. 다만 합치면서 시각이
사라지는 것은 참조 적재기의 결함이었습니다.** 짚어 주신 덕분에 발견했고, 보완본을 첨부드립니다.

## 1. 합치는 것은 의도입니다

V4.8 그래프는 건별 기록을 **쌍 단위 관계 1개로 접고**, 기간과 건수를 속성으로 남기는 방식입니다
(규격서 §4 — 통화·이체와 같은 원칙). 위치(`located_at`)는 온톨로지상 ATM·기관 같은 대상의
**위치 관계**이므로, (주체, 위치)당 1개가 되는 것이 정상입니다. 말씀하신 위치 1,207건 → `located_at`
380개는 이 규칙대로 접힌 결과입니다. IP(`used_ip`)도 (주체, IP)당 1개입니다.

## 2. 시각이 사라진 것은 결함이었습니다 — 보완 완료

기존 참조 적재기는 합칠 때 시각을 제대로 남기지 못했습니다.

| 관계 | 기존 동작 (결함) | 보완 후 |
|---|---|---|
| `used_ip` | 행마다 덮어써 **마지막 행**의 `valid_from`·`access_type`·출처만 남음 | `valid_from`(최초 접속) · `valid_to`(마지막 관측) · `usage_count`(접속 건수) · `access_type`(관측된 값 전부) · `source_id`(출처 전부) |
| `located_at` | `evt_ymdhm`을 **저장하지 않음**, 출처도 마지막 행만 | `first_dt` · `last_dt` · `evt_count`(시각 있는 건수) · `source_id`(출처 전부). 시각 없는 정적 위치(ATM 설치 위치 등)는 시각 속성 없이 둡니다 |

예) 같은 전화번호가 한 IP로 3번 접속했다면:
```
used_ip {valid_from:'2026-03-01 09:00:00', valid_to:'2026-03-05 14:00:00', usage_count:3,
         access_type:'banking|web', source_id:'DOC-1|DOC-2'}
```
통화 발신기지국·이체 거래점 위치, 이체 IP에도 같은 규칙이 적용됩니다. 온톨로지 전달본(Python·XLSX)의
속성 정의도 함께 갱신했습니다.

## 3. 귀 기관에서 하실 일

- **CSV는 바꾸실 필요가 없습니다.** 지금처럼 건별 원본으로 주시면 됩니다(규격 변경 없음).
- 이미 적재하신 그래프에 시각 속성을 채우시려면, **보완본 적재기로 새 그래프에 다시 적재**해 주십시오.
  ```
  python3 load_csv_to_graph.py <CSV폴더> --graph <그래프명> --reset
  ```
  ⚠ `--reset` 없이 기존 그래프에 같은 자료를 다시 넣으면, 보완본은 "이미 반영된 자료"로 판단해
  건너뛰므로 시각 속성이 채워지지 않습니다. (보완본은 재적재·분할 납품 시 중복이 생기지 않도록
  출처 기준으로 판정합니다.)
- 재적재 후 `located_at` 개수는 그대로(380개)이고, 각 관계에 `first_dt`·`last_dt`·`evt_count`가
  채워지면 정상입니다.

## 4. 참고

건별 시각(예: "3월 11일 14시대 접속")이 필요한 분석은 그래프의 요약 관계가 아니라 원본 기록으로
합니다. CSV를 건별로 주시는 이유가 이것입니다.
