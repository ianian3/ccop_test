요청하신 **예제 파일 16종과 컬럼 설명을 첨부**드렸습니다.

## 1. 먼저 확인 부탁드릴 사항 — `tbl_eg_mtl.csv`

보내주신 목록 9종 중 `tbl_eg_mtl.csv`는 저희 규격에 없는 이름입니다. 나머지 8종은 정확히
일치하고, 저희 9번째 파일은 **`tbl_eg_rmt.csv`(계좌 이체)** 입니다. 파일 수와 자리가
맞아떨어져 같은 파일을 가리키는 것으로 보고 첨부 규격서는 `tbl_eg_rmt` 기준으로 작성했습니다.

`mtl`이 다른 종류의 데이터라면 **헤더 1행만 보내주시면** 해당 항목을 추가해 회신드리겠습니다.

## 2. 파일별 추가 컬럼

기존 컬럼은 모두 유지되며, 아래가 V4.8에서 추가되는 항목입니다.

| 파일 | 추가 컬럼 |
|---|---|
| `tbl_vt_psn` | `psn_id` · `dob` · `gender` · `nationality` · `occp_nm` · **`source_id`** |
| `tbl_vt_telno` | `telco_nm` · `join_typ_cd` · `subs_holder` · `is_burner` · **`source_id`** |
| `tbl_vt_bacnt` | **`bank_cd`** · `account_type` · `bacnt_opn_dt` · **`source_id`** |
| `tbl_eg_case` | `damage_amt` · `crime_site` · **`source_id`** |
| `tbl_eg_case_prsn` | **`source_id`** |
| `tbl_eg_call` | **`channel`** · `bsst_addr`(발신기지국주소) · **`source_id`** |
| `tbl_eg_telno_poss` | `psn_id` · `valid_from` · `valid_to` · **`source_id`** |
| `tbl_eg_bactno_poss` | `psn_id` · `bank_cd` · `valid_from` · `valid_to` · **`source_id`** |
| `tbl_eg_rmt` | `bank_cd` · `rlt_bank_cd` · `ip_addr`(거래 IP) · `brnch_nm`(거래점) · **`source_id`** |

## 3. 이 중 꼭 챙겨주셨으면 하는 3가지

나머지는 있으면 채우고 없으면 비워두셔도 되지만, 아래 셋은 데이터 정확성에 직접 영향이 있습니다.

**① `source_id` (전 파일)** — 그 행이 어느 원본 문서에서 왔는지 구분할 수 있는 값이면 무엇이든
됩니다(예: `DOC-001`, `2026-00123-계좌영장-3`). 파일 단위로 같은 값이어도 무방합니다.
이 값이 없으면 나중에 "이 관계는 어느 자료에서 나왔는지"에 답할 수 없어, 수사 산출물로 쓰기
어려워집니다. 저희 통합 그래프는 전체 24,720개 노드가 100% 보유하고 있습니다.

**② `bank_cd` (계좌 관련 파일)** — 현행 적재는 은행코드를 고정값 `999`로 저장합니다. 그래서
**은행이 달라도 계좌번호 문자열이 같으면 한 계좌로 합쳐지는** 문제가 있습니다. V4.8은 계좌를
`계좌번호 + 은행코드`로 식별하므로 이 값을 주시면 해소됩니다. 코드를 모르시면 기존처럼
`bank`(은행명)만 주셔도 저희가 변환합니다.

**③ `channel` (통화 파일)** — V4.8은 연락 관계를 하나로 모으고 수단을 이 값으로 구분합니다
(`call`/`sms`/`kakao`/`naver` 등). 비어 있으면 전부 음성통화로 간주되어 문자·메신저가 통화
건수에 섞입니다. 문자·메신저는 종료시각이 없으므로 `end_ymdhm`은 비워두시면 됩니다.

## 4. 통화·이체 데이터는 **건별 원본 그대로** 주십시오

집계는 플랫폼에서 처리합니다. V4.8 그래프는 통화·이체를 상대방 쌍마다 1개로 접고 첫/마지막
시각과 건수·합계를 속성으로 답니다. 건별 시각은 그래프가 아니라 표준 RDB가 보관하는 구조라,
미리 집계해 주시면 "3월 11일 14시대 통화" 같은 조회가 불가능해집니다.

## 5. 신규 파일 7종 (해당 데이터가 있을 때만)

기존 9종으로는 담을 수 없던 종류입니다. 특히 **IP 접속 기록은 저희 2차년도 통합 그래프에서
15,348건으로 가장 많이 쓰인 관계**인데 받을 파일이 없었습니다.

- `tbl_vt_ip` / `tbl_eg_ip_use` — IP와 사용 주체
- `tbl_vt_id` / `tbl_eg_id_use` / `tbl_eg_id_msg` — 메신저·포털 계정, 계정 간 대화
- `tbl_vt_loc` / `tbl_eg_loc_use` — 기지국·ATM·영업점 위치

## 6. 납품 전 자체 검증 도구

첨부한 `validate_csv_v48.py`로 보내시기 전에 직접 확인하실 수 있습니다. DB 접속이 필요 없고
파이썬 표준 라이브러리만 사용하므로 폐쇄망에서도 그대로 동작합니다.

```
python3 validate_csv_v48.py <CSV 폴더>
```

파일명 인식 여부, 인코딩(UTF-8), 필수 컬럼, 컬럼명 오타, 날짜·숫자 형식, 코드값, `source_id`,
그리고 **파일 간 참조 정합**(관계 파일이 가리키는 인물·전화·계좌가 노드 파일에 있는지)까지
확인해 문제가 있는 파일·행·컬럼을 알려줍니다. 첨부 예제 폴더로 실행해 보시면 통과 상태가
어떤 모습인지 보실 수 있습니다.

## 7. 예제 파일 안내

16종 모두 하나의 시나리오로 서로 연결되도록 작성했습니다(인물 3·전화 3·계좌 2·사건 2·IP 2·
계정 2·위치 2). 컬럼을 어떻게 채우는지 참고하실 수 있고, 그대로 적재하면 작은 사건 그래프가
만들어집니다. 예제의 IP는 문서 예시 전용 대역(RFC 5737)이라 실제 호스트와 무관합니다.
