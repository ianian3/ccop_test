## 1. 먼저 확인 부탁드릴 사항 — `tbl_eg_mtl.csv`

보내주신 목록 9종 중 `tbl_eg_mtl.csv`는 저희 규격에 없는 이름입니다. 나머지 8종은 정확히
일치하고, 저희 9번째 파일은 **`tbl_eg_rmt.csv`(계좌 이체)** 입니다. 파일 수와 자리가 맞아떨어져
같은 파일을 가리키는 것으로 보고, 첨부 규격서는 `tbl_eg_rmt` 기준으로 작성했습니다.

`mtl`이 다른 종류의 자료라면 **헤더 1행만 보내주시면** 해당 항목을 추가해 회신드리겠습니다.

## 2. 만드실 파일은 13종입니다

`templates.zip` 에 헤더만 들어 있는 빈 CSV 13개를 넣었습니다. 그대로 열어 값을 채우시면 됩니다.
UTF-8 BOM으로 저장돼 있어 Excel에서 바로 열어도 한글이 깨지지 않고, 컬럼은 **왼쪽부터 중요한
순서**(필수 → 선택 → `source_id`)로 배치했습니다.

| | 파일 | |
|---|---|---|
| **필수 9종** | `tbl_vt_psn` · `tbl_vt_telno` · `tbl_vt_bacnt` · `tbl_eg_case` · `tbl_eg_case_prsn` · `tbl_eg_telno_poss` · `tbl_eg_bactno_poss` · `tbl_eg_call` · `tbl_eg_rmt` | 지금 만들고 계신 것 그대로 |
| **선택 4종** | `tbl_eg_ip_use` · `tbl_eg_id_use` · `tbl_eg_id_msg` · `tbl_eg_loc_use` | 해당 자료가 있을 때만 |

선택 4종 중 **IP 자료(`tbl_eg_ip_use`)는 가급적 주시면 좋겠습니다.** 저희 통합 그래프에서
15,348건으로 가장 많이 쓰인 관계이고, 서로 다른 사건을 잇는 단서가 대부분 여기서 나옵니다.

## 4. 이 중 꼭 챙겨주셨으면 하는 3가지

**① `source_id` — 전 파일**
그 행이 어느 원본 문서에서 왔는지 구분할 수 있는 값이면 무엇이든 됩니다(예: `DOC-001`,
`2026-00123-계좌영장-3`). 파일 단위로 같은 값이어도 무방합니다. 이 값이 없으면 나중에 "이 관계는
어느 자료에서 나왔는지"에 답할 수 없어 수사 산출물로 쓰기 어려워집니다. 저희 통합 그래프는
전체 24,720개 노드가 100% 보유하고 있습니다.

**② `bank_cd` — 계좌 파일**
현행 적재는 은행코드를 고정값 `999`로 저장합니다. 그래서 **은행이 달라도 계좌번호 문자열이
같으면 한 계좌로 합쳐지는** 문제가 있습니다. V4.8은 계좌를 `계좌번호 + 은행코드`로 식별하므로
이 값을 주시면 해소됩니다. 코드를 모르시면 기존처럼 `bank`(은행명)만 주셔도 저희가 변환합니다.

**③ `channel` — 통화 파일**
V4.8은 연락 관계를 하나로 모으고 수단을 이 값으로 구분합니다(`call`/`sms`/`kakao`/`naver` 등).
비어 있으면 전부 음성통화로 간주되어 문자·메신저가 통화 건수에 섞입니다. 문자·메신저는
종료시각이 없으므로 `end_ymdhm`은 비워두시면 됩니다.

## 5. 통화·이체는 **건별 원본 그대로** 주십시오

집계는 플랫폼에서 처리합니다. V4.8 그래프는 통화·이체를 상대방 쌍마다 하나로 접고 첫/마지막
시각과 건수·합계를 속성으로 답니다. 건별 시각은 그래프가 아니라 표준 RDB가 보관하는 구조라,
미리 집계해 주시면 "3월 11일 14시대 통화" 같은 조회가 불가능해집니다.

## 6. 첨부 도구 2종

**`validate_csv_v48.py` — 보내시기 전 자체 점검**
DB 접속이 필요 없고 파이썬 표준 라이브러리만 사용하므로 폐쇄망에서도 그대로 동작합니다.

```
python3 validate_csv_v48.py <CSV 폴더>
```

파일명 인식 여부, 인코딩, 필수 컬럼, 컬럼명 오타, 날짜·숫자 형식, 코드값, `source_id`, 그리고
**파일 간 참조 정합**(관계 파일이 가리키는 인물·전화·계좌가 노드 파일에 있는지)까지 확인해
문제가 있는 파일·행·컬럼을 짚어 줍니다.

**`load_csv_to_graph.py` — 적재 참조 구현**
규격서가 약속한 동작을 그대로 구현한 코드입니다. 어떤 CSV가 어떤 노드·엣지가 되는지, 통화·이체가
어떻게 집계되는지를 문서가 아니라 코드로 확인하실 수 있습니다. 그대로 쓰셔도 되고, 귀사 적재기를
구성하실 때 기준으로 삼으셔도 됩니다. 필요한 패키지는 `psycopg2` 하나입니다.

적재는 멱등이라 **사건별·문서별로 나눠 보내셔도 됩니다.** 2차·3차 납품분은 기존 데이터에
덧붙고, 계좌번호·전화번호·IP가 겹치면 서로 다른 자료에서 온 정보라도 자동으로 이어집니다.

## 7. 예제 파일

`examples.zip` 은 **템플릿과 같은 13종에 값을 채운 것**이라 파일명이 1:1로 대응합니다. 빈 템플릿을
열고 같은 이름의 예제를 보시면 됩니다. 13종 모두 하나의 시나리오로 연결되도록 작성해서, 그대로
적재하면 작은 사건 그래프가 만들어집니다(인물 3·전화 3·계좌 2·사건 2·IP 2·계정 2·위치 3).

예제의 IP는 문서 예시 전용 대역(RFC 5737)이라 실제 호스트와 무관합니다.
